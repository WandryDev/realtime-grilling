# Спайк: локальный STT для ru/uk (риск №2 из concept.md)

Дата: 2026-11-02. Код: `spikes/stt/`. Модели, аудио и сырые логи лежат в gitignored `models/`, `data/`, `runs/`. Полные таблицы всех прогонов: `spikes/stt/results.md`.

## Итог

- **Apple Silicon: идём.** Whisper large-v3-turbo q5_0 (файл 547 МБ, ~0.8 ГБ памяти), whisper.cpp + Metal, MacBook Air M3: **1.26 с на фразу p50, 1.68 с p95**, Σ RTF 0.26. Время почти не зависит от длины фразы. Загрузка модели < 1 с. С глоссарием на «телефонном» аудио: **WER ru 3.7 %, uk 7.7 %**, имена 13/13, термины 24/25, числа 20/20.
- **Без VAD Whisper выдаёт текст на 100 % клипов без речи** («Продолжение следует...», «Дякую за перегляд!», «Редактор субтитров…»). Пороги `no_speech`/`logprob` в whisper.cpp не убрали ни одной галлюцинации. **С Silero VAD — 0 из 120.** Фильтр приложения (пороги по сегментам + стоп-лист) оставляет 40 % (остаются «Дякую»: настоящее слово, стоп-листом его не убрать). VAD перед моделью обязателен.
- **Глоссарий в `prompt` — главный рычаг качества.** Термины: 14/25 → 24/25, WER падает примерно вдвое. Перегруженный промпт (~900 символов) на речи не протёк в текст, но качество откатилось до уровня «без глоссария»: uk термины 58 %, имена 10/13. Причина: whisper.cpp обрезает начало длинного промпта. **Утечка промпта есть на тишине:** `small` + обычный глоссарий 3 раза выдал сам глоссарий («Техноком, Олег Ковальчук, Bitrix24, ClickUp…») с уверенным logprob −0.07. Пороги такое не ловят, нужен VAD и проверка «ответ ≈ промпт».
- **Числа и отрицания.** У turbo числа 20/20. Отрицания 14/15: во всех моделях Whisper фраза «не пізніше» превращается в «на певніше» (безударное «не» на телефонном/синтетическом аудио). `small` на uk теряет числа и отрицания (16/20, 13/15). `medium` один раз «дописал» число: «максимум 250» → «250 000».
- **GigaAM v3 работает** через sherpa-onnx (wheel под Python 3.13 есть). CPU, **0.2–0.35 с на фразу**, ~0.4 ГБ, 0 галлюцинаций на тишине. Обычный русский текст распознаёт точнее turbo: WER по фразам без терминов 0.9 % против 1.8 %. Но англ. термины проваливает (4/13; «вебхук» → «век», «API» → «IPI»), а глоссария у него нет.
- **Windows без GPU — не измерено.** Оценка (ниже): turbo там в реальном времени **не тянет** (7–50 с на фразу). Реальные варианты: GigaAM для ru, `small` для uk ценой качества, облако.

**Решение: «идём» для macOS (Apple Silicon); для Windows — «нужны данные (Windows-железо, реальные записи)».** Подход «фразы после VAD → turbo + глоссарий» менять не нужно. Неизвестно другое: сколько менеджеров сидят на Windows без нормальной видеокарты и каков WER на живой речи.

> **Оговорка: данные синтетические.** Речь сгенерирована macOS `say`, по одному голосу на язык; «телефонный» тракт смоделирован. TTS говорит чётче людей: нет перебиваний, акцентов, эха и настоящего шума. Англ. термины TTS произносит неестественно. На реальных звонках абсолютный WER будет **хуже**. Переносимы в основном **относительные** выводы (глоссарий, VAD, сравнение моделей) и **задержки**: они от содержания почти не зависят. 38 фраз — мало: одна фраза меняет ключевые метрики на 2.5–5 п.п.

## Метод

- **Набор** — `spikes/stt/phrases.json`. 38 фраз discovery-звонка про систему приёма звонков, CRM и интеграции: 20 ru (голос `Milena`) и 18 uk (`Lesya`), длина 2.0–12.6 с, всего 202 с. Намеренно включены:
  - имена людей и компаний;
  - англ. термины: API, webhook, Bitrix24, ClickUp, amoCRM, KeyCRM, Binotel, Ringostat, Asterisk, SIP, SLA, Slack, Google Sheets;
  - числа: 15/50, 200 000, даты, рубли/копейки;
  - отрицания и «ловушки» к ним («нужна» рядом с «не нужна»);
  - 3 фразы суржика (uk16–18) и одна ru-фраза с англицизмами.

  TTS читает термины так, как их произносит русско-/украиноязычный человек («вебхук», «си-ар-эм»), а числа — словами. Эталон записан с цифрами и латиницей.
- **Аудио.** `clean` — 16 кГц mono. `call` — розовый шум (SNR ≈ 20 дБ) → полоса 300–3400 Гц → Opus 16 кбит/с туда-обратно → 16 кГц. Плюс 5 клипов без речи: цифровая тишина; белый шум −65 дБ; розовый «room tone» −40 дБ; коричневый шум через телефонный тракт; шум 3 с через тракт.
- **Задержка.** `whisper-server` (whisper.cpp 1.9.2, Homebrew, Metal) поднимается один раз на модель. Загрузка = от старта процесса до первого HTTP-ответа (файл в кеше ОС). Каждая фраза — отдельный POST, время меряется на клиенте (wall-clock).
  - Фразы идут **в темпе реального времени**: следующая не раньше, чем через длительность предыдущей, как в живом звонке.
  - Первые 2 запроса — прогрев, в статистику не входят.
  - Жадный декодинг, temperature 0 с fallback, язык задан явно.
  - Флаг `-nlp` обязателен: без него `verbose_json` делает лишний проход энкодера ради вероятностей языков, и задержка растёт вдвое (замерено: 2.3 с против 1.2 с).
- **Память.** Peak RSS через psutil и `peak memory footprint` из `/usr/bin/time -l` (учитывает Metal-буферы).
- **Качество.** Свой скорер `score.py`, без зависимостей. Нормализация:
  - lower-case, ё→е, без пунктуации и апострофов;
  - числительные ru/uk (с падежами и порядковыми) → цифры; «150 000» → 150000;
  - валюта (₽ / руб / рубля → руб);
  - фиксированный список алиасов кириллица → латиница («битрикс 24» → bitrix24).

  WER и CER считаются по группе фраз целиком (корпусные). Отдельно по разметке проверяются имена, термины, числа и отрицания. Для отрицаний проверяется и то, что лишнее «не» не появилось. Термины считаются двумя способами: **strict** — латиница как в эталоне; **lenient** — после алиасов, т.е. смысл передан. «WER без терминов» считается по 11 ru / 10 uk фразам без англ. терминов.
- **Глоссарий** (`prompt` = `initial_prompt`): 16 имён и терминов на язык, ~170 символов. **Перегруз:** ~900 символов, 50+ терминов, посторонние имена и темы.
- **Галлюцинации.** 5 клипов × ru/uk × 2 повтора = 20 запросов на конфиг × 6 конфигов × 3 модели. Фильтр приложения выкидывает сегмент, если `no_speech_prob > 0.6`, или `avg_logprob < −1`, или сегмент совпал со стоп-листом фантомных фраз.
- **GigaAM v3** (ru): sherpa-onnx 2.0.1; k2-fsa `nemo-ctc-giga-am-v3` и `nemo-transducer-punct-giga-am-v3`, обе int8, лицензия MIT; CPU.
- **Железо.** MacBook Air 13" M3 (Mac15,12, без вентилятора), CPU 4P+4E, GPU 10 ядер, 16 ГБ, macOS 26.6.
  - **Машина была общей:** параллельно работали чужие процессы, load average местами 40–150. Каждый запрос помечен `load1`, задержки ниже взяты из запросов при load ≤ 8. Сырые p95 в `results.md` местами завышены именно этим.
  - Стресс-прогон «впритык» на троттлинг не завершён (рестарт хоста и чужая нагрузка).

## Выводы

- **Галлюцинации.**
  - VAD перед моделью обязателен; пороги whisper.cpp сами по себе ничего не дают.
  - Защита в глубину: стоп-лист фантомов; отбрасывать ответ, если он совпадает с промптом (≥ 3 термина глоссария подряд, которых нет в соседних фразах); не передавать предыдущий текст как контекст (каждая фраза — отдельный запрос).
  - Не обрезать VAD-сегмент вплотную к речи: Silero `speech_pad` 30–100 мс.
- **Глоссарий.**
  - Держать ≤ ~150 токенов: только имена и термины проекта и людей на звонке, без фраз и тем.
  - Перегруз молча режет начало промпта и ухудшает качество.
  - Глоссарий не помогает с глаголами, предлогами и с «не».
- **Числа.** Turbo и medium надёжны: 100 % на нашем наборе. Но medium показал, что модель может «дописать» порядок («250» → «250 000»). Для summary и вопросов числа стоит сверять в пост-проходе (beam 5 + полный глоссарий) и подсвечивать в UI.
- **Отрицания.** Единственная устойчивая ошибка всех Whisper-моделей — потеря безударного «не» (uk10). Риск «не нужно ↔ нужно» реален и должен проверяться на живых записях. Агенту стоит отдавать вопросы с отрицаниями «под подтверждение», а не как факт.
- **GigaAM против turbo для ru.** GigaAM точнее на обычной речи и в 4–6 раз дешевле, но без глоссария теряет термины — а именно на них строятся вопросы discovery. Маршрутизация «ru → GigaAM» оправдана только там, где нет GPU. На Mac проще один turbo.

## Windows: оценка (НЕ измерено, по публичным данным)

У turbo тот же энкодер, что у large-v3 (32 слоя), и именно он — основная цена на CPU. Поэтому для оценки годятся замеры энкодера `large`: одно 30-секундное окно на фразу.

| CPU | что замерено | время | источник |
|---|---|---|---|
| Apple M3, 4 P-ядра (этот спайк) | turbo q5_0 / small, фраза целиком | 13.2 с / 4.2 с | `results.md` |
| Ryzen 7 PRO 8845HS (8C/16T, 2024, топ-ноутбук) | turbo q5_0, 16 потоков, 30-с окно | энкодер 6.9 с, всего 7.4 с | [whisper-xdna](https://github.com/felipe-NR/whisper-xdna) |
| i7-11800H (8C, 2021) | энкодер large, 8 потоков / small | 27.7 с / 4.8 с (сборка 2022 г.) | [whisper.cpp #89](https://github.com/ggml-org/whisper.cpp/issues/89) |
| i5-1135G7 (4C, 2020) | энкодер medium, 8 потоков | 24.9 с (сборка 2025 г.) → large ≈ 50 с (×2 по FLOPs) | [#89](https://github.com/ggml-org/whisper.cpp/issues/89) |
| Ryzen 5 4500U (6C) | энкодер small, 6 потоков | 6.4 с (2022) | [#89](https://github.com/ggml-org/whisper.cpp/issues/89) |

**Оценка для ноутбука без GPU:**

- **turbo:** 7 с на фразу на топовом 8-ядерном (2023–24), 15–50 с на типичном 4–6-ядерном U-series. Это в 3–15 раз медленнее порога → **нет**.
- **turbo с `audio_ctx 768`:** примерно в 3.5 раза быстрее (на M3 13.2 → 3.7 с), т.е. 2–15 с. Плюс потеря качества и фантомные хвосты → **нет**, на топовых CPU — на грани.
- **small:** 1–2 с на топовых, 3–7 с на типичных → **на грани**, и качество uk плохое.
- **GigaAM v3:** на M3 RTF 0.04–0.07 на 1–4 потоках. Если x86-ядро в 2–4 раза медленнее, получится RTF 0.1–0.3, т.е. 0.5–1.5 с на фразу → **да** (тоже оценка).

## Онбординг-проверка «тянет ли машина реальное время»

`bench.py` — её прототип: `--limit 3 --passes call:none` даёт ~1 минуту и вердикт `realtime_ok` в `runs/<tag>.meta.json`.

**Что мерить:**

1. **Загрузку модели с диска.** Только для UX: прогресс-бар, не порог.
2. **Задержку на ~6 встроенных call-like фразах** длиной 3, 6 и 12 с (ru + uk), после 1 прогревочной, в темпе реального времени. Считать p95 задержки и Σ RTF = Σ задержек / Σ длительностей.
3. **Санити-WER по встроенным эталонам**, порог < 15 %. Ловит сломанный GPU-бэкенд или драйвер, который быстро выдаёт мусор.
4. **Пиковую память** против свободной RAM.
5. **То же в фоне во время первых реальных звонков:** скользящий p95 и длину очереди фраз. Это ловит троттлинг и звонилку, которая ест CPU. При деградации — понизить модель и предложить облако.

**Пороги:**

- **p95 ≤ 3 с на фразу до 15 с и Σ RTF ≤ 0.5.** Запас ×2 — на троттлинг безвентиляторных ноутбуков, на саму звонилку с эхоподавлением и на всплески, когда говорят оба канала.
- **Лестница моделей:** turbo q5_0 (GPU) → [ru: GigaAM v3 | uk: small] → облако.
- **Пример:** M3 Metal turbo q5_0 — p95 1.7 с, Σ RTF 0.26 → проходит. M3 без GPU turbo — 13 с → не проходит.

## Как воспроизвести

**macOS (Apple Silicon)**

```bash
brew install whisper-cpp ffmpeg python@3.13
cd spikes/stt
python3.13 -m venv .venv && .venv/bin/pip install psutil numpy sherpa-onnx
# модели (официальный HF-репозиторий whisper.cpp) + Silero VAD
mkdir -p models && cd models
for f in large-v3-turbo large-v3-turbo-q8_0 large-v3-turbo-q5_0 medium small; do
  curl -L -o ggml-$f.bin https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-$f.bin; done
curl -L -o ggml-silero-v5.1.2.bin https://huggingface.co/ggml-org/whisper-vad/resolve/main/ggml-silero-v5.1.2.bin
mkdir -p gigaam && cd gigaam
for n in sherpa-onnx-nemo-ctc-giga-am-v3-russian-2025-12-16 sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16; do
  curl -L https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/$n.tar.bz2 | tar xj; done
cd ../..
.venv/bin/python make_dataset.py         # синтетический набор -> data/ (нужны `say` и ffmpeg с libopus)
./run_mac.sh                              # вся матрица, ~2 ч в темпе реального времени; закройте тяжёлые приложения
.venv/bin/python score.py                 # таблицы -> runs/report.md
# быстрая онбординг-проверка (~1 мин):
.venv/bin/python bench.py --model models/ggml-large-v3-turbo-q5_0.bin --tag check --limit 3 --passes call:none
```

**Windows (CPU / CUDA / Vulkan)**

1. На Mac выполнить `make_dataset.py` и скопировать `spikes/stt/data/` на Windows: голоса `say` есть только на macOS.
2. Поставить Python 3.12/3.13 (`py` launcher).
3. Скачать whisper.cpp с [Releases](https://github.com/ggml-org/whisper.cpp/releases) (сборка `b5454` / v1.9.5):
   - **CPU:** `whisper-bin-x64.zip`. Внутри `whisper-server.exe`, `whisper-bench.exe` и DLL с выбором AVX2/AVX-512 в рантайме. Распаковать в `spikes\stt\whisper\`.
   - **NVIDIA:** `whisper-bin-win-cuda-12.4.0-x64.zip` → `spikes\stt\whisper-cuda\`.
   - **Vulkan (iGPU / AMD):** готовой сборки нет. Нужны Vulkan SDK, VS 2022 и CMake, затем `cmake -B build -DGGML_VULKAN=1 && cmake --build build --config Release` → `build\bin\Release`.
4. GigaAM (по желанию): скачать и распаковать два архива из `asr-models` (ссылки выше) в `spikes\stt\models\gigaam\`, например `tar -xf <файл>.tar.bz2` (tar есть в Windows 10+).
5. Запуск из `spikes\stt`:

   ```powershell
   powershell -ExecutionPolicy Bypass -File run_windows.ps1 -Bin .\whisper\Release            # CPU
   powershell -ExecutionPolicy Bypass -File run_windows.ps1 -Bin .\whisper-cuda\Release -Tag cuda
   powershell -ExecutionPolicy Bypass -File run_windows.ps1 -Bin <whisper.cpp>\build\bin\Release -Tag vulkan
   powershell -ExecutionPolicy Bypass -File run_windows.ps1 -Bin .\whisper\Release -Quick     # онбординг-проверка
   ```

   Скрипт сам скачивает `small`, `turbo q5_0` и Silero VAD, пишет `runs\<tag>-machine.txt` (CPU/GPU/RAM), `runs\<tag>-whisper-bench.txt` (энкодер, сравнимо с #89), `runs\*.meta.json` (`realtime_ok`, `p95_latency_s`, `total_rtf`, пиковая память) и `runs\report.md`.
6. Прислать каталог `runs\` для 3–5 типичных ноутбуков менеджеров. По `runs\report.md` закрывается строка «Windows» в рекомендациях.

**Что нужно, чтобы закрыть риск:** (1) замеры `run_windows.ps1` на реальном парке Windows; (2) 5–10 реальных звонков с вычитанными транскриптами, прогнанные через `bench.py` / `score.py` (формат эталонов — `phrases.json`) — особенно отрицания, числа и имена на живой речи; (3) стресс-тест в темпе звонка ≥ 30 мин на безвентиляторном Mac при работающей звонилке.
