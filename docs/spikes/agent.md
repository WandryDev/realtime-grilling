# Спайк: задержка и стоимость вызова агента (Claude Code CLI)

> Дата: 2026-11-02. Claude Code CLI 2.1.316, вход по подписке, macOS (Apple Silicon). Риск №3 из `docs/concept.md`.
> Харнес и входные данные: `spikes/agent/`. Сырые логи: `spikes/agent/runs/` (в git не попадают).

## TL;DR

- **Sonnet в минимальном режиме укладывается в 20 с:** p50 ≈ 13 с, p95 ≈ 17–18 с, 0 таймаутов. Haiku 5.5 через CLI **не укладывается** (p50 22–28 с): даже при `--effort low` модель думает по 3–7 тыс. токенов, а выключить thinking через CLI нельзя.
- **Конфиг пользователя по умолчанию — нет:** +3 с на старт (хуки, плагины, 15 MCP), ~44 тыс. токенов префикса, кеш каждый раз перезаписывается на ~28 тыс. токенов. Выходит $0.14 за вызов против $0.04 в минимальном режиме.
- **Стоимость (API-эквивалент, Sonnet):** ≈ $0.04 за вызов, **$3.6 за звонко-час при 90 вызовах, $7.2 при 180**. Почти половина входа каждого вызова — запись в кеш с TTL 1 ч по двойной цене. Этим управляет CLI, а не мы.
- **Качество формата:** 70 из 70 ответов — валидный JSON по схеме. Все ID в `evidence` существуют, 96–100% цитат нечётко совпадают с транскриптом.
- **Решение: «идём»** — CLI + Sonnet в минимальном режиме для MVP. Интерфейс «Агент» сразу проектируем под замену на прямой API: это даёт управление thinking, кешем и строгим структурированным выводом. Главный открытый риск — лимиты подписки (см. ниже).

## Метод

**Входные данные** (`spikes/agent/inputs/`, всё на русском, синтетика):

- `system.md` — протокол патчей (`create_card`, `update_card`, `mark_answered`, `add_question` с `evidence` / `card_field` / `gap_type` / `priority`) и правила качества из концепта. Явно разрешён пустой патч, не больше 2 вопросов за вызов, не больше 3 `update_card`.
- `brief.md` — бриф «Единая система приёма звонков» для сети клиник, пункты B1–B12. `people.md` — 3 профиля клиента (P1–P3).
- `state.json` — 2 карточки, 5 открытых вопросов (Q1–Q5).
- `transcript.txt` — discovery-звонок на 26 минут: 188 сегментов, ~3000 слов, каналы «Я» и «Остальные». В тексте есть ошибки ASR, смена темы и противоречия в числах и в «нужно / не нужно».
- `patch.schema.json` — JSON Schema патча.

**Вызов.** Стабильный префикс (системный промпт + бриф + профили, ≈4 тыс. токенов) передаётся через `--system-prompt`. В конец префикса добавлен ID звонка, чтобы первый вызов каждой конфигурации был холодным. Переменная часть (состояние + последние 10 минут транскрипта, 5–12 тыс. символов) идёт через stdin. Вызов k получает транскрипт до минуты t_k = 3, 5.5, 8 … 25.5. Состояние статичное, патчи не применяются. Каждый вызов — отдельный процесс; вызовы идут строго последовательно из временной папки вне репо, таймаут 90 с.

**Метрики** берутся из `stream-json` с `--include-partial-messages`:

- `init` — событие `system/init`.
- TTFT — первый `content_block_delta` любого типа, включая thinking.
- «1-й вывод» — первый `text_delta` или `input_json_delta`.
- wall — от spawn до выхода процесса.
- Токены и `total_cost_usd` — из `result`; `modelUsage` показывает побочные вызовы.

**Минимальный режим:** `--setting-sources "" --strict-mcp-config --tools "" --no-session-persistence --disable-slash-commands`. В `init` он даёт 0 MCP, 0 skills, 0 user-плагинов и 0 инструментов; со схемой остаётся 1 инструмент, `StructuredOutput`.

**`--bare` с подпиской не работает:** он читает только `ANTHROPIC_API_KEY` и возвращает «Not logged in», без вызова модели.

**Модели:** алиасы `sonnet`, `haiku` и `opus` резолвятся в `claude-sonnet-5-5`, `claude-haiku-5-5` и `claude-opus-5-5`. Везде задан `--effort low`.

## 1. Накладные расходы CLI (тривиальный промпт, Haiku, 4 вызова)

| Режим | wall p50 / p95 | init p50 | spawn → первый байт API | префикс, токенов |
|---|---|---|---|---|
| Минимальный | 2.8 / 3.9 с | 0.5 с | 2.2 с | ~3.6k (дефолтный системный промпт CC) |
| По умолчанию (OMC, 7 плагинов, 15 MCP, хуки) | 7.2 / 8.5 с | 3.3 с | 5.4 с | ~39k |

Первый запуск процесса «с холода» стоит ещё +1–3 с (первый вызов за сессию — 5.7 с wall).

## 2. Задержка реалистичного вызова (секунды)

| Конфигурация | n | wall p50 | wall p95 | TTFT p50 / p95 | 1-й вывод p50 | init p50 | холодный → тёплые p50 |
|---|---|---|---|---|---|---|---|
| **A. Sonnet, минимальный, `--json-schema`** | 10 | **12.8** | **17.2** | 3.1 / 7.2 | 7.8 | 0.3 | 5.2* → 13.1 |
| H. Sonnet, как A + `DISABLE_NONESSENTIAL_TRAFFIC` (рекомендуемый) | 6 | 13.1 | 18.0 | 3.0 / 8.4 | 8.4 | 0.8 | 14.0 → 13.1 |
| C. Sonnet, минимальный, JSON только по промпту | 10 | 17.4 | 26.6 | 4.7 / 11.1 | 12.9 | 0.2 | 8.6* → 18.2 |
| B. Haiku, минимальный, `--json-schema` | 10 | 21.7 | 31.8 | 1.9 / 2.3 | 18.3 | 0.2 | 10.8* → 21.9 |
| D. Haiku, минимальный, JSON по промпту | 10 | 28.1 | 38.7 | 1.7 / 3.5 | 24.9 | 0.2 | 17.8* → 30.8 |
| E. Sonnet, конфиг по умолчанию, `--json-schema` | 5 | 20.6 | 25.2 | 6.0 / 15.7 | 15.4 | 3.0 | 19.0 → 20.6 |
| F. Opus, минимальный, `--json-schema` | 3 | 11.9 | 16.9 | 3.5 / 5.4 | 3.5 | 0.4 | 9.2 → 11.9 |
| G. Sonnet, как A, но `--append-system-prompt` | 3 | 18.9 | 22.1 | 8.5 / 8.7 | 13.7 | 4.3 | 18.9 → 18.4 |

\* Холодный вызов в A–D приходится на t = 3 мин, когда транскрипт короткий. Честное сравнение на одном входе (Sonnet, k = 4): холодный кеш — 14.0 с / $0.055, тёплый — 12.1 с / $0.040. По времени кеш почти ничего не даёт: префилл ~10k токенов быстрый. Даёт он деньги.

Таймаутов и ошибок — 0 из 70. Около 80% времени вызова занимает генерация: Sonnet выдаёт ~1.3–1.5 тыс. токенов, из них ~550–700 thinking.

Что видно по таблице:

- **Схема быстрее, чем «JSON по промпту»** (12.8 против 17.4 с): без схемы модель думает в 2 раза дольше.
- **Haiku 5.5 медленнее Sonnet**: thinking 3.6–5 тыс. токенов за вызов, и `--effort low` его не убирает.
- **Opus 5.5 на `low` почти не думает** (0–190 токенов). По задержке он не хуже Sonnet, но в 2 раза дороже; выборка мала (n = 3).
- **Thinking через CLI не выключить:** `CLAUDE_CODE_DISABLE_THINKING=1` и `--settings '{"alwaysThinkingEnabled":false}'` проверены, thinking остаётся.
- **Как устроен `--json-schema`.** Это не нативный structured output, а инструмент `StructuredOutput` плюс принуждение. Если модель сначала пишет JSON текстом, CLI добавляет синтетическое сообщение «You MUST call the StructuredOutput tool…» и делает второй запрос. На первой версии промпта это давало 25 с и двойной вывод. После фразы «передай патч вызовом инструмента StructuredOutput» в user-сообщении — всегда 1 API-запрос на вызов.

## 3. Токены, кеш, стоимость

Средние на вызов. $ = `total_cost_usd` (API-эквивалент по прайсу, `costBasis: list`).

| Конфигурация | cache write | cache read | output (thinking) | доля кеш-хита (тёплые) | $/вызов холодный | $/вызов тёплый | **$/звонко-час @90** | **@180** | токенов/звонко-час @180 |
|---|---|---|---|---|---|---|---|---|---|
| A. Sonnet min schema | 5.8k | 5.0k | 1334 (547) | 49% | 0.034 | 0.038 | **3.4** | **6.9** | 3.4M |
| H. Sonnet min schema rec | 6.7k | 4.7k | 1485 (679) | 47% | 0.055 | 0.040 | **3.6** | **7.2** | 2.3M |
| C. Sonnet min prompt | 5.8k | 3.7k | 1968 (1153) | 43% | 0.034 | 0.045 | 4.0 | 8.1 | 3.3M |
| B. Haiku min schema | 6.0k | 4.9k | 4641 (3657) | 49% | 0.003 | 0.004 | 0.39 | 0.78 | 2.9M |
| D. Haiku min prompt | 5.8k | 3.7k | 6013 (5038) | 43% | 0.004 | 0.005 | 0.45 | 0.90 | 2.9M |
| E. Sonnet по умолчанию | 31.8k | 13.0k | 1895 (1035) | 36% | 0.197 | 0.136 | 12.3 | 24.5 | 9.6M |
| F. Opus min schema | 7.8k | 3.6k | 1156 (63) | 47% | 0.112 | 0.075 | 6.7 | 13.4 | 3.5M |
| G. Sonnet append | 8.6k | 5.1k | 1531 (697) | 56% | 0.071 | 0.041 | 3.7 | 7.4 | 3.9M |

Как читать таблицу:

- Некешированный `input` — 2 токена: CLI ставит кеш-маркер на всё сообщение.
- Звонко-час @180 — потолок при каденсе 20 с; реалистично меньше (триггер по паузе), поэтому @90 — рабочая оценка.
- Колонка токенов включает побочный вызов Haiku: ~6k входных токенов на каждый вызов, если не выставлен `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`.
- `duration_api_ms` ≈ `duration_ms`. Накладные расходы CLI сверх API — 0.2–1.3 с в минимальном режиме и 3–4 с по умолчанию.

**Попадает ли стабильный префикс в кеш между независимыми вызовами — да.** С `--system-prompt` тёплые вызовы стабильно читают из кеша ~5.4k токенов: наш префикс, служебный блок CLI ~1.3k и определение `StructuredOutput`. Системный промпт CLI между запусками не меняется.

**Что ломает кеш или делает его дорогим:**

1. **Переменная часть всегда пишется в кеш с TTL 1 ч** (`ephemeral_1h`, цена записи 2×). Это ~6k токенов на вызов, и повторно они не читаются: окно транскрипта каждый раз другое. Это главная статья расходов, и в CLI ею не управлять.
2. **Любое изменение префикса** даёт холодную запись ~4–5k токенов: смена брифа или профилей, ID звонка в промпте, другая модель, другая схема (она живёт в определении инструмента). На Sonnet это +$0.015, на Opus — +$0.04. Раз в звонок — несущественно.
3. **Конфиг по умолчанию:** из ~44k токенов префикса тёплый вызов читает из кеша только 16k, остальные ~28k каждый раз пишутся заново. Это хуки, плагины и MCP. В тривиальных вызовах 1 из 4 тоже перезаписал 23k.
4. **`--append-system-prompt`** держит кеш (+2.2k токенов дефолтного промпта CC), но этот промпт содержит динамические секции (cwd, дата, git) и сломается при их смене. Ещё в этом режиме init был медленнее (1.9–6.5 с; причину не выясняли). **Использовать `--system-prompt`.**

## 4. Лимиты подписки

**Напрямую лимиты подписки измерить нельзя.** `total_cost_usd` — это API-эквивалент, а не расход лимита. Единственный косвенный сигнал — событие `rate_limit_event` в `stream-json`: `utilization` окон 5 ч и 7 дней с шагом 0.01.

Наблюдение грубое: параллельно на том же аккаунте работала сессия оркестратора, поэтому это оценка сверху. Окно 5 ч:

| Прогон | Сдвиг окна 5 ч | API-эквивалент |
|---|---|---|
| 10 вызовов Sonnet | +2 п.п. | ~$0.4 |
| 10 вызовов Haiku | +1 п.п. | ~$0.04 |
| Весь спайк | 0.05 → 0.25 | $2.55 |

Окно 7 дней за весь спайк: 0.09 → 0.10.

Экстраполяция (порядок величины, тариф аккаунта не определяли):

- Один звонко-час на Sonnet при 90 вызовах/ч ≈ **15–20 п.п. 5-часового окна**, при 180 вызовах/ч ≈ 30–40 п.п.
- Значит, ~3–5 часов звонков подряд на одном аккаунте могут упереться в 5-часовой лимит — особенно если менеджер параллельно пользуется Claude Code.
- Недельное окно: ~1.5–3% за звонко-час.

**Что нужно руководству для сравнения с лимитами плана** (на менеджера, Sonnet, минимальный режим):

| Метрика | Значение |
|---|---|
| Вызовов в час | 90 (реалистично) … 180 (максимум) |
| Токенов на вызов | вход ~11.4k (6.7k запись в кеш + 4.7k чтение) + выход ~1.5k |
| Токенов на звонко-час @90 | ~0.6M записи в кеш, ~0.42M чтения, ~0.13M выхода |
| API-эквивалент | $3.6 за звонко-час @90 (@180 — $7.2) |
| При 3 ч звонков в день × 22 дня | ≈ $240–475 на менеджера в месяц |
| 10 менеджеров | ≈ $2.4–4.7k в месяц |

Перед решением нужен замер `utilization` на 1–2 живых звонках на целевом тарифе.

## 5. Качество вывода (санити)

| Конфигурация | валидный JSON | по схеме | пустых патчей | ops / вопросов на вызов | ID в evidence существуют | цитата ≥ 0.8 | факты `update_card` из канала «Я» |
|---|---|---|---|---|---|---|---|
| A. Sonnet schema | 10/10 | 10/10 | 0/10 | 4.9 / 0.4 | 100% | 99% | 0/53 |
| C. Sonnet prompt | 10/10 (без чистки) | 10/10 | 0/10 | 5.2 / 0.4 | 100% | 99% | 0/56 |
| B. Haiku schema | 10/10 | 10/10 | 0/10 | 6.3 / 1.4 | 100% | 100% | 0/60 |
| D. Haiku prompt | 10/10 (без чистки) | 10/10 | 0/10 | 6.1 / 1.5 | 100% | 100% | 3/62 |
| E / F / G / H | 17/17 | 17/17 | 0/17 | 5.0–6.0 / 0–1.0 | 100% | 96–100% | 0/107 |

- Нечёткое совпадение цитаты — нормализация плюс скользящее окно Левенштейна, порог 0.8. ID в `evidence` проверялись по окну транскрипта или по брифу.
- **Пустых патчей нет** — артефакт статичного состояния: каждый вызов видит «новые» факты относительно исходных карточек. С применением патчей пустые ответы должны появиться; это проверим в режиме прогона.
- Лимит «≤ 2 вопросов» и «≤ 3 `update_card`» соблюдён везде. Sonnet задаёт мало вопросов (0.4 за вызов) и активно закрывает открытые (`mark_answered` — 17 из 10 вызовов). Haiku задаёт в 3–4 раза больше вопросов, есть повторы по смыслу.

Примеры вопросов (`add_question`):

- Sonnet: «Артём, можно ли через API МИС по номеру телефона проверить, появилась ли у пациента запись после пропущенного звонка?» — `C2.integrations`, `assumption`, `blocker`.
- Haiku: «Бинотел показал 22% пропущенных, а вы называли до 30% — какую цифру считаем базовой?» — `C1.acceptance`, `contradiction`.
- Sonnet (повторяется в двух соседних вызовах — нужна дедупликация в коде, как в концепте): «Если все операторы колл-центра заняты, пациент ждёт в очереди или звонок уходит на филиалы?»

Пример патча (Sonnet, t = 20:30, сокращено):

## 6. Прямой API

`ANTHROPIC_API_KEY` в окружении нет, поэтому прямой API не замерялся. Что он изменил бы (оценки, не замеры):

- **Управление thinking.** У Sonnet 5.5 есть `thinking: {type: "between_tools"}`, у Haiku 5.5 — `disabled` при effort ≤ high. Thinking — это ~4–5 с из 13 у Sonnet и ~15–25 с у Haiku. Haiku без thinking, по оценке, давал бы ~5–8 с за ~$0.002 за вызов — в 10–20 раз дешевле Sonnet.
- **Явный `cache_control` только на префиксе, TTL 5 мин** (каденс 20 с держит кеш тёплым). Переменная часть оплачивается как обычный вход ($2/M), а не запись в кеш с TTL 1 ч ($4/M). Sonnet: ≈ $0.028 против $0.040 за вызов (−30%), без thinking ≈ $0.02.
- **Строгий structured output** (`output_config.format`) — без инструмента-обёртки и без риска лишнего «принуждающего» запроса.
- **Нет старта CLI:** −0.3–1.3 с. Можно держать соединение, стримить и разбирать `ops` по мере генерации.
- **Минус:** оплата по API вместо подписки, ключи в Keychain, собственный ретрай и учёт расходов.

## Рекомендуемый вызов для интерфейса «Агент» (Claude Code)

```bash
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 claude -p \
  --model claude-sonnet-5-5 --effort low \
  --setting-sources "" --strict-mcp-config --tools "" \
  --no-session-persistence --disable-slash-commands \
  --system-prompt "$STABLE_PREFIX" \
  --json-schema "$PATCH_SCHEMA" \
  --output-format stream-json --verbose --include-partial-messages \
  < volatile_user_message.txt
```

- Модель — полное имя, а не алиас: алиас может переехать на новую модель и сбросить кеш или поведение.
- В конце user-сообщения: «Передай патч одним вызовом инструмента StructuredOutput». Без этого бывает второй запрос (+10 с).
- Результат брать из `result.structured_output`. Таймаут 30 с. Новый вызов не стартует, пока идёт предыдущий: при p95 ≈ 18 с каденс 20 с держится без наложений.
- `--bare` не использовать: требует API-ключ. `--system-prompt`, а не `--append-system-prompt`. Запускать из постоянной папки данных приложения, а не из проекта пользователя.
- Логировать из `rate_limit_event` `utilization`, чтобы показывать менеджеру близость к лимиту.

## Решение

**«Идём»** — CLI (Claude Code, Sonnet, минимальный режим) для MVP и прототипа.

- Вызов укладывается в 20 с (p50 13 с, p95 17–18 с) при 100% валидном выводе и честных ссылках на основания.
- Интерфейс «Агент» с первого дня закладываем с реализацией на прямом API. Переключаемся, если:
  - замер `utilization` на живых звонках покажет, что подписки не хватает (оценка — 15–20 п.п. 5-часового окна за звонко-час);
  - или понадобится задержка < 10 с: на API выключается thinking, Haiku становится реальным вариантом, кеш дешевле на ~30%.
- Haiku через CLI и конфиг пользователя по умолчанию для быстрого контура не годятся.

## Живой прогон в приложении (2026-11-04)

Быстрый контур из `openspec/changes/agent-fast-loop` в подписанном debug-бандле на MacBook Air M3. Было 3 записи, около 25 минут разговора. Клиента играл скрипт `spikes/fake-client/`: реплики писал Claude, озвучивал `say -v Milena` через системный звук.

Вызовы в 2–4 раза быстрее, чем в спайке. Причины две: ответы короче (200–550 токенов вывода), и в окне всего несколько минут расшифровки, а не 10.

Что заметили:

- **Агент не реагирует, если клиент сидит в той же комнате и говорит в микрофон «Я».** Так задумано: факты и запуск вызова идут только от «Остальных».

Качество вопросов (точность, покрытие) — задача «Качество вопросов».

## Живой прогон с брифом (2026-11-05)

Проект «Обменник» (SK Exchange). Описание проекта и один источник, `bug-bot-knowledge-simple.md` (14,6 тыс. символов). Звонок с живым собеседником длился 75 минут, речь смешанная, русская и украинская.

**Бриф.** Собран примерно за 45 с: файл добавлен в 11:48:48, бриф сохранён в 11:49:35. В это время входит и работа мастера. Материалы не сокращались. В глоссарии 28 терминов из словаря документа: Planfix, підкріплення, USD МІКС, зношені, декрет и другие. Стоимость сборки не записана: в отличие от `agent_calls`, сборка брифа не логирует токены.

| Метрика | Значение |
|---|---|
| Вызовов агента | 271: 64 с операциями, 207 пустых, 0 ошибок и таймаутов |
| Длительность вызова p50 / p95 / max | 3.3 / 8.8 / 16.2 с |
| Вопросов создано | 7, клиент ответил на 6 |
| Отброшено проверкой | 1 операция (`quoteNotFound`) |
| Кеш на вызов, в среднем | чтение 6,5 тыс. токенов, запись 8,9 тыс. токенов |
| Стоимость | $0.038 за вызов, $10.2 за звонок (API-эквивалент) |

Что заметили:

- **До исправления `82b01b2` каждый патч с первым вопросом откатывался.** Проверка пропускала вопрос `empty` о поле, которого нет в карточке, а сохранение такое поле требовало. Тема пропадала вместе с патчем, и окно показывало «Тема ещё не ясна».
- **Вызов стал в 2,7 раза дороже, чем без брифа.** Каждый вызов заново пишет в кеш около 9 тыс. токенов. Значит, стабильная часть промпта не попадает в кеш целиком, и это стоит разобрать.
- **Вопросы иссякают, когда карточка почти заполнена.** Последний новый вопрос появился на 21-й минуте, за оставшиеся 55 минут не было ни одного, хотя поле `users` пустое, а разговор перешёл на «промежуточного бота». Новую тему агент не создал. Это задача «Качество вопросов».
- **Украинские реплики распознаются плохо** («пункта, каќе, Деякс»). По таким обрывкам агент не находит ни фактов, ни цитат.
