# Proposal

## Why

Шаги онбординга «Разрешения» и «Агент» сейчас работают на таймерах (`src/data/onboarding-setup.ts`, `OnboardingBackend.layerMock`). Пользователь может «выдать» доступ к микрофону и системному звуку или «найти» Claude Code, которых на компьютере на самом деле нет. Каркас приложения, хранилище и мост к Rust уже готовы (`app-shell-and-storage`), спайки подтвердили, как устроены разрешения macOS и вызов Claude Code CLI (`docs/spikes/audio.md`, `docs/spikes/agent.md`). Пора подключить эти шаги к настоящей системе: это задача 3 «Онбординг окружения» в ClickUp, и без неё нельзя начинать захват звука и агента.

## What Changes

- **Разрешения ОС (бэкенд).** Команды читают состояние доступа к микрофону и к записи системного звука, запрашивают его (системный диалог macOS) и открывают нужный раздел системных настроек.
  - **macOS.** Микрофон — через AVFoundation. Системный звук («Только запись системного аудио») — запросом через короткий process tap, состояние — через проверку TCC с запасным вариантом «неизвестно».
  - **Windows.** Микрофон — по настройкам конфиденциальности (реестр), системный звук разрешения не требует.
  - В бандл macOS добавляются `NSMicrophoneUsageDescription`, `NSAudioCaptureUsageDescription` и entitlement `com.apple.security.device.audio-input`.
- **Агент Claude Code (бэкенд).** Команды находят `claude` (GUI-приложение не видит PATH из shell), узнают версию и статус входа через `claude auth status --json`, устанавливают CLI официальным установщиком с прогрессом и запускают вход в браузере, после чего ждут, пока вход завершится. Найденный путь сохраняется в настройках для будущего агента.
- **Проверка звука (бэкенд).** Живой уровень сигнала (0–1, ~10 раз в секунду) для микрофона и для системного звука. Окно подписывается на событие уровня, остановка — при отписке.
- **Фронтенд.** У `OnboardingBackend` появляется `layerTauri`. Шаги «Разрешения» и «Агент» и индикаторы уровня работают на реальных статусах. Таймеры из `onboarding-setup.ts` переезжают в `layerMock`, хуки и экраны не меняются. При возврате фокуса в окно онбординга статусы перечитываются.
- **Права окон.** Новые команды доступны окнам онбординга и главному (будущие настройки), но не плавающим окнам.

**Не входит:**
- Скачивание модели речи и расшифровка в проверке микрофона — это задача STT, шаг «Речь» остаётся на `layerMock`.
- Запись звонка, эхоподавление и детектор «микрофон занят» — задача «Захват звука и запись».
- Интеграции (шаг 05) — задача «Агент: быстрый и медленный контур, интеграции».
- Флаг пройденного онбординга — уже в настройках (`onboardingCompleted`).

## Capabilities

### New Capabilities
- `system-permissions`: состояние, запрос и восстановление доступа приложения к микрофону и к записи системного звука на macOS и Windows.
- `agent-setup`: поиск, установка, вход и проверка готовности локального CLI агента (Claude Code).
- `audio-check`: живой уровень входного сигнала микрофона и системного звука для проверок перед звонком.

## Impact

- **Rust (`src-tauri`).**
  - Новые модули: `permissions`, `agent`, `audio/level`.
  - Новые зависимости: `objc2` / `objc2-av-foundation` / `block2` (macOS), `windows` с регистром и WASAPI (Windows), `cpal` для уровня микрофона, `which` для поиска CLI.
  - Новые команды и события в `src/bindings.ts`.
  - Изменения в `command_names.rs`, `capabilities/main.json`, `Info.plist`, `Entitlements.plist`, `tauri.macos.conf.json`.
  - Код tap/loopback переносится из `spikes/audio`.
- **Фронтенд.**
  - `src/features/onboarding/backend.ts` (контракт и два слоя), `src/data/onboarding-setup.ts` (действия через сервис), `src/effect/runtime.ts` (`OnboardingBackend.layerTauri` в `TauriLayer`).
  - Тесты контракта и экранов в режиме Tauri (`fake-tauri.ts`).
- **Сборка и разработка.** TCC привязывает доступ к подписи. При ad-hoc подписи macOS спрашивает доступ после каждой пересборки, поэтому для разработки нужна стабильная локальная подпись (описать в README).
- **Проверка.** Windows-часть проверяется вручную на машине менеджера, как и аудио-спайк.
