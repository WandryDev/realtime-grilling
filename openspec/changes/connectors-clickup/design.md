## Context

`connectors-outline` построил каркас:
- `ConnectorKind` с ClickUp в `available: false`, `AuthMethod::ApiKey { host }`, трейты `Connector` и `SourceProvider` (`browse`, `resolve`, `fetch`);
- `SecretStore` на Keychain, общая синхронизация `sync_project` с одной транзакцией и полётами (`SyncFlights`);
- таблицы `connections`, `connector_selections`, `project_connector_sync` и `project_sources` с `account_ref`;
- команды `connector_*`, сервис `Connectors` и экраны Outline.

Каркас писался с расчётом на ClickUp, но в нём есть три места, рассчитанные на Outline:
- дерево выбора двухуровневое: коллекции сверху, внутри документы, загруженные целиком;
- подключение по ключу всегда даёт одну команду;
- фронтенд выбора и блок источников называются и написаны под Outline (`OutlinePickerDialog`, `OutlineSources`).

Что известно об API ClickUp v2 (developer.clickup.com):
- **Токен.** Личный токен `pk_…` передаётся заголовком `Authorization: pk_…`, без `Bearer`. Токен бессрочный.
- **Вход и пространства.** `GET /user` возвращает пользователя, `GET /team` — рабочие пространства (teams), доступные токену.
- **Иерархия.** `GET /team/{id}/space?archived=false`, `GET /space/{id}/folder?archived=false`, `GET /space/{id}/list?archived=false` (списки без папки), `GET /folder/{id}/list?archived=false`. У списка есть `task_count`.
- **Задачи.** `GET /team/{id}/task` фильтрует по `space_ids[]`, `project_ids[]` (папки) и `list_ids[]`. Есть `subtasks`, `include_closed`, `order_by=updated`, `include_markdown_description` и `date_updated_gt`. Страница — 100 задач, размер не настраивается. `GET /task/{id}?include_subtasks=true&include_markdown_description=true` возвращает одну задачу.
- **Комментарии.** `GET /task/{id}/comment` отдаёт 25 последних, от новых к старым; следующая страница — по `start` и `start_id` последнего комментария.
- **Лимит запросов.** На токен: 100 в минуту на Free, Unlimited и Business, 1 000 на Business Plus, 10 000 на Enterprise. В ответах есть `X-RateLimit-Limit`, `X-RateLimit-Remaining` и `X-RateLimit-Reset` (Unix-время). При превышении приходит 429.

## Goals / Non-Goals

**Goals:**
- ClickUp на том же каркасе: то же хранение, та же синхронизация, те же команды и экраны, без новой миграции.
- Общий выбор с вложенными контейнерами, на котором встанет и GitHub (организация → репозиторий).
- Синхронизация, которая укладывается в 100 запросов в минуту и не падает на лимите.

**Non-Goals:**
- OAuth, входящие вопросы, запись в ClickUp, ClickUp Docs, вложения.
- Несколько рабочих пространств в одном подключении.

## Decisions

### 1. Вход: `ApiKey { host: false }` и выбор пространства

- **Описание.** У ClickUp `AuthMethod::ApiKey { host: false }`, возможность `ProjectSources`, `available: true`. Ссылка на страницу токена: `https://app.clickup.com/settings/apps`.
- **Проверка.** `verify` вызывает `GET /user` и `GET /team`. Если пространство одно, `Account { host: None, team_id, team_name, user_name }`.
- **Несколько пространств.** `ConnectOutcome` получает третий вариант: `chooseWorkspace { workspaces: [{ id, name }] }`. Секрет не пишется, строка `connections` не создаётся. У команды `connector_connect_api_key` появляется необязательный аргумент `workspace: Option<String>`. Интерфейс вызывает её снова с тем же токеном из поля и выбранным id. Пространство, которого нет в ответе `/team`, даёт `rejected { field: key }` («Токен не открывает это пространство»).
- **В `Connector`.** Появляется метод `verify_in(session, workspace: Option<&str>) -> Result<Verified, _>`, где `Verified` — `Account` или `Choose(Vec<Workspace>)`. У Outline реализация по умолчанию оборачивает `verify`.
- **Хранение.** Выбранное пространство записывается в `Account.team_id` и в `Session`: синхронизация ходит только в него. `account_ref` у источников — id пространства, поэтому защита «источники другой команды» из `connectors-outline` работает без изменений.

Альтернатива — показывать все пространства верхним уровнем дерева. Отвергнута:
- `account_ref` и правило «одно подключение — один аккаунт» пришлось бы переделывать;
- в макете онбординга подключается одно пространство.

### 2. Дерево: вложенные контейнеры, id с префиксом

- **Типы.** `RefKind` остаётся `Container | Document`. Id контейнеров ClickUp несут префикс: `space:<id>`, `folder:<id>` и `list:<id>`, у задачи — голый id. Так выбор, исключения и `external_id` в `project_sources` не меняют схему, а `resolve` по префиксу понимает, что фильтровать.
- **`browse`.**
  - `None` — пространства.
  - `space:` — папки и списки без папки.
  - `folder:` — списки.
  - `list:` — открытые задачи списка верхнего уровня, с подзадачами в `children`. Это одна страница или несколько по 100, не больше 200 задач, иначе дерево не нужно.
- **Счётчик.** `document_count` берётся из `task_count` списка, у папки это сумма её списков. У пространства счётчика нет до раскрытия, и `has_children: true`.
- **Фронтенд.** Выбор Outline становится общим `ConnectorPickerDialog` с `kind`:
  - любой контейнер раскрывается и сам загружает детей через `browseChildren`, загрузки не повторяются;
  - ошибка загрузки показывается в узле с «Повторить»;
  - у Outline коллекция возвращает дерево документов одним ответом, как сейчас, так что поведение Outline не меняется;
  - поиск ищет по загруженным узлам и раскрывает найденные.
- **Исключение.** Исключить можно любой узел внутри выбранного контейнера: список внутри выбранного пространства или задачу внутри выбранного списка. `Exclude` хранит id с префиксом.
- **Лимит в выборе.** Счётчик выбора примерный, когда в нём есть нераскрытое пространство. Точную проверку делает `connector_selection_set`, который уже отвергает выбор больше 200 через `resolve`. Выбор показывает этот отказ как сообщение о лимите и ничего не сохраняет.

### 3. `resolve` и `fetch` для ClickUp

**Контейнеры.**
- Один проход `GET /team/{id}/task` с фильтрами `space_ids[]`, `project_ids[]` и `list_ids[]` из выбора, параметрами `subtasks=true`, `include_markdown_description=true` и `order_by=updated`, по страницам. Закрытые задачи не берутся (`include_closed=false`).
- Задачи, которые лежат в нескольких списках, склеиваются по id.
- Исключённые контейнеры отсеиваются по `list.id`, `folder.id` и `space.id` задачи, исключённые задачи — по id.
- Подзадачи исключённой задачи тоже отсеиваются, по `parent`.

**Отдельные задачи.**
- `GET /task/{id}?include_subtasks=true&include_markdown_description=true`: задача остаётся источником в любом статусе, её подзадачи берутся только открытые.
- 404, 401 на задачу из чужого пространства и архивная задача (`archived: true`) — пункт `unavailable`.

**Недоступный контейнер.** Его нет в выдаче:
- перед проходом `resolve` проверяет каждый выбранный контейнер одним запросом: `GET /list/{id}`, `/folder/{id}` или `/space/{id}`;
- 404 или 401 — `unavailable`;
- архивный контейнер — тоже `unavailable`.

**Лимит 200.**
- Задачи идут от новых изменений к старым, первые 200 становятся источниками, остальные считаются.
- Для подсчёта проход идёт до конца выдачи, но не дальше 20 страниц. Больше 2 000 задач показывается как «больше 1 800 не загружены».

**Версия и текст.**
- Версия задачи — `date_updated`.
- `prefetched` нет: текст включает комментарии, а их выдача списка не даёт.
- `fetch` для изменённых задач берёт описание из ответа `resolve` и загружает комментарии: до двух страниц, то есть до 50 последних.

**Формат текста.**
```
# <название>
Статус: <статус> · Список: <папка / список> · Исполнители: <имена>

<markdown_description>

## Комментарии
**<автор>, <дата>:** <comment_text>
```
Комментарии идут от старых к новым внутри взятых 50.

**Закрытая задача** — статус с `type: closed`. Статусы `done` считаются открытыми: в ClickUp это «готово к проверке», клиенту про это ещё может быть что спросить.

### 4. Ограничитель запросов

- **Где живёт.** Клиент ClickUp держит общий на подключение `RateGate`: остаток и время сброса из заголовков последнего ответа.
- **Остаток кончился.** Если остаток 0, а сброс в будущем, запрос ждёт до сброса плюс 1 секунду. Ожидание прерывается, когда отменяют полёт синхронизации.
- **429.** Ждём до `X-RateLimit-Reset`. Если заголовка нет, ждём 60 секунд. Повторов до 5, после этого `ConnectorError::Unreachable` («ClickUp ограничил запросы»). Эта ошибка не считается отзывом.
- **Без заголовков.** Если ClickUp не прислал заголовков лимита, запросы идут с паузой не меньше 600 мс: 100 запросов в минуту.
- **Параллельность.** Не больше 4 одновременных запросов на подключение. Комментарии в `fetch` загружаются тоже через это ограничение.
- **Перед звонком.** `brief_prepare` ждёт синхронизацию 30 секунд, как у Outline. Полёт после этого не отменяется и завершается в фоне. Пока он идёт, `project_connector_sync` показывает «идёт синхронизация». Тест на виртуальном времени: лимит исчерпан, звонок начинается, полёт заканчивается позже.
- **Таймауты.** У каждого запроса 15 секунд, как у Outline.

Альтернатива — загружать комментарии только по «Обновить». Отвергнута: тогда текст источника зависел бы от того, как его обновили.

### 5. Синхронизация без изменений в движке

`sync_project` уже сравнивает версии, загружает только изменённое, пишет одной транзакцией и останавливается на `Unauthorized`. От ClickUp движку нужна только реализация `SourceProvider`.

Длинная первая синхронизация (до 200 задач и около 2–3 минут на тарифе со 100 запросами в минуту) пишет результат одной транзакцией в конце. Промежуточного сохранения нет: бриф в это время собирается по прежним источникам.

### 6. Фронтенд

- **Подключение.** Диалог подключения в настройках и экран ClickUp в онбординге вводят токен через `MaskedKeyInput`, без поля адреса. Ответ `chooseWorkspace` показывает радиогруппу пространств и кнопку «Подключить». Экран ClickUp в онбординге с макетом OAuth (`clickup-connect-screen.tsx`) переписывается на этот поток, демо-состояния в `/dev` обновляются.
- **Источники.** `OutlineSources` становится `ConnectorSources` с `kind`; Outline и ClickUp рисуются отдельными блоками со своими подписями: «документы» или «задачи», «Выбрать в Outline» или «Выбрать в ClickUp». Подписи берутся из `src/features/connectors/labels.ts`.
- **Каталог.** Строки «скоро» остаются только у GitHub. Имитации ClickUp в `layerMock` и в `src/data/integrations.ts` переходят на вход по токену, имитация OAuth удаляется.

## Risks / Trade-offs

- **[Комментарий может не менять `date_updated`]** → Если ClickUp не обновляет `date_updated` у задачи при новом комментарии, синхронизация его не увидит. Проверяется в ручном прогоне. Если подтвердится, добавим версии из `date` последнего комментария через выборочную проверку при «Обновить». Это отдельная задача в tasks.md, по результату прогона.
- **[`task_count` считает не только открытые задачи]** → Счётчик выбора приблизительный. Точная проверка лимита идёт в `connector_selection_set`.
- **[Первая синхронизация занимает минуты]** → Блок ClickUp показывает «Синхронизация…» и сколько задач уже прочитано. Бриф до конца синхронизации собирается по прежним источникам.
- **[Личный токен видит всё, что видит менеджер]** → Приложение только читает. Токен лежит в Keychain и не уходит агенту, как ключ Outline.
- **[Изменение зависит от неархивированного `connectors-outline`]** → Сначала архивируется `connectors-outline`, потом этот. Ветка `feat/clickup` идёт от `feat/connectors`.

## Migration Plan

Миграции базы нет. ClickUp раньше был «скоро», поэтому подключений и выбора ClickUp в базах нет. Откат — вернуть `available: false`.

## Отклонения при реализации

- **Отключение прерывает синхронизацию.** `SyncFlights` держит handle прерывания полёта, и `disconnect` отменяет идущие синхронизации коннектора, у Outline тоже. Ожидание лимита завершается вместе с полётом, а ждущие получают «Синхронизация прервана».
- **Проход по задачам отдельный для каждого вида контейнера** (`space_ids[]`, `project_ids[]`, `list_ids[]`). ClickUp не документирует, как эти фильтры сочетаются. Отдельные проходы верны при любом сочетании и вместе ограничены 20 страницами.
- **Описание задачи идёт в `RemoteDoc.prefetched`**: заголовок и описание из `resolve`. `fetch` всегда добавляет комментарии.
- **Ограничение 20 страниц.** Если задач больше 2 000, источники показывают «1 800 не загружены», без «больше».
- **Ограничитель запросов.**
  - «До 5 повторов»: шестой 429 даёт `Unreachable`.
  - После 429 ожидание идёт до сброса, не меньше 1 с.
  - Любое ожидание не длиннее 61 с.
  - Запрос вычитается из остатка до отправки.
  - Пауза 600 мс действует и до первого ответа, пока заголовков ещё нет.
- **401 на отдельном списке или задаче** проверяется одним `GET /user` на `resolve`. Если токен рабочий, пункт `unavailable`, иначе синхронизация останавливается с `Unauthorized`.
- **Пространство при подключении проверяется и у Outline**: команда с другим id отвергается.
- **Возможности ClickUp** — только `ProjectSources`, без `Inbox` и `Publish`.
- **Фронтенд.**
  - Демо в браузере стартует с подключённым ClickUp «Pixel Agency», а демо-токен открывает два пространства.
  - Если при повторном открытии выбора в нём есть сохранённый список или папка внутри нераскрытого пространства, счётчик показывает «примерно N».
  - Поиск идёт по загруженным узлам и до задач нераскрытых списков не доходит.
  - «Синхронизация…» показывается без числа прочитанных задач.
  - Плашки выбранных контейнеров ClickUp пишут «все задачи».
