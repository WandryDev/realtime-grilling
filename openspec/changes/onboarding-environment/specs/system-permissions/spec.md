## Purpose

Доступ приложения к микрофону («Я») и к записи системного звука («Остальные») на macOS и Windows: узнать текущее состояние, попросить доступ и помочь его включить, если пользователь отказал. Без этих доступов звонок не записать.

## ADDED Requirements

### Requirement: Состояние доступа
Приложение SHALL сообщать фронтенду состояние каждого из двух доступов — к микрофону и к записи системного звука — одним из значений:
- `notDetermined` — ещё не спрашивали;
- `granted` — разрешено;
- `denied` — отказано, ограничено политикой или выключено в настройках;
- `unknown` — ОС не даёт узнать состояние без попытки записи.

Чтение состояния MUST NOT показывать системный запрос доступа.

#### Scenario: Первый запуск на macOS
- **WHEN** пользователь впервые открывает шаг «Разрешения»
- **THEN** микрофон в состоянии `notDetermined`, и системный диалог не появляется, пока пользователь не нажал «Разрешить»

#### Scenario: Доступ уже выдан
- **WHEN** доступ к микрофону выдан раньше, например при прошлом запуске
- **THEN** шаг сразу показывает микрофон как разрешённый

#### Scenario: Системный звук на Windows
- **WHEN** приложение запущено на Windows
- **THEN** доступ к системному звуку в состоянии `granted`: для записи звука других приложений Windows разрешения не требует

### Requirement: Запрос доступа
По нажатию «Разрешить» приложение SHALL вызвать системный запрос доступа, если ОС его поддерживает, и вернуть итоговое состояние после ответа пользователя. Если доступ уже `denied`, повторный запрос MUST NOT считаться успешным. В этом случае фронтенд предлагает открыть системные настройки.

#### Scenario: Пользователь разрешил микрофон на macOS
- **WHEN** пользователь нажимает «Разрешить» и соглашается в системном диалоге macOS
- **THEN** состояние микрофона становится `granted`, шаг показывает уровень сигнала

#### Scenario: Пользователь отказал
- **WHEN** пользователь нажимает «Не разрешать» в системном диалоге
- **THEN** состояние становится `denied`, шаг показывает подсказку и кнопку «Открыть настройки»

#### Scenario: Микрофон выключен в настройках Windows
- **WHEN** на Windows доступ к микрофону для классических приложений выключен в параметрах конфиденциальности
- **THEN** состояние микрофона `denied`, а «Разрешить» открывает нужный раздел параметров

### Requirement: Открытие системных настроек
Приложение SHALL открывать раздел системных настроек, где включается конкретный доступ: «Микрофон» или «Запись экрана и системного аудио» на macOS, «Конфиденциальность → Микрофон» на Windows. Если точный раздел открыть нельзя, SHALL открываться ближайший общий раздел конфиденциальности.

#### Scenario: Включить доступ после отказа
- **WHEN** пользователь нажимает «Открыть настройки» у отказанного доступа к микрофону на macOS
- **THEN** открываются «Системные настройки → Конфиденциальность и безопасность → Микрофон»

### Requirement: Повторная проверка без перезапуска
Приложение SHALL перечитывать состояние доступов по кнопке «Проверить» и когда окно онбординга снова получает фокус, без перезапуска приложения. Если ОС применяет изменённый доступ только после перезапуска приложения, фронтенд SHALL сказать об этом пользователю, а не показывать доступ как выданный.

#### Scenario: Доступ включён в настройках
- **WHEN** пользователь включил доступ в системных настройках и вернулся в окно онбординга
- **THEN** шаг показывает доступ как разрешённый, а «Продолжить» становится доступной

### Requirement: Описание причины доступа
Сборка для macOS SHALL содержать понятные пользователю описания на русском, зачем нужен микрофон и запись системного звука. Без них macOS не показывает запрос.

#### Scenario: Текст в системном диалоге
- **WHEN** macOS показывает запрос доступа к микрофону
- **THEN** в диалоге написано, что Grill слушает звонок и расшифровывает его на этом компьютере
