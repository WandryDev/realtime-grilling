# Design

## Context

Что есть сейчас:

- **Rust (`src-tauri/`)** — шаблон: одно окно 800×600 и команда `greet`.
- **Фронтенд** — Next.js 16, static export в `out/`:
  - маршруты окон: `/`, `/onboarding`, `/widget`, `/overlay`;
  - сущности открываются по `?id=` (`src/lib/routes.ts`), динамических сегментов нет.
- **Данные** лежат в in-memory сторах `src/data/*` на `createStore` (`useSyncExternalStore`) и засеяны моками из `src/features/*/mock.ts`. Id проекта — slug из названия.
- **Имитация бэкенда.** Projects уже на Effect-сервисе (`ProjectsBackend` + `layerMock`, композиция в `src/effect/runtime.ts`). Шесть областей ещё на `api.ts` с таймерами.
- **Компоненты окна.**
  - Заголовок уже размечен `data-tauri-drag-region="deep"`.
  - В дизайн-системе есть `WindowTrafficLights` (рисунок macOS) и `WindowControls` (кнопки Windows).
  - В настройках есть `launchAtLogin`, `hideOnShare` и `shortcuts`.
- **Тесты.** 244 теста Vitest рендерят экраны на моках синхронно.

Требования — в `specs/app-shell`, `specs/local-storage` и `specs/backend-bridge`.

## Goals / Non-Goals

**Goals:**

- Rust владеет данными и побочными эффектами ОС: окна, трей, автозапуск, горячие клавиши. Фронтенд только вызывает команды и слушает события.
- Mock-режим в браузере и тестах ведёт себя как сейчас: текущие тесты проходят без переписывания под асинхронную загрузку.
- Контракт Rust ↔ TS один, и его нельзя рассинхронизировать незаметно.

**Non-Goals:**

- Пул соединений и конкурентная запись: пользователь один, писатель один.
- Оптимистичные обновления в сторах.
- Детальная схема полей карточки задачи и патчей агента. Они отложены концептом и хранятся в JSON-колонках до задач 6 и 8.
- WebDriver-тесты настоящего окна Tauri.

## Decisions

### Окна

**1. Окна объявлены статически в `tauri.conf.json`.**

- Метки окон: `main`, `onboarding`, `widget`, `overlay`. У всех `visible: false`.
- В `setup` Rust читает настройку `onboardingCompleted` и показывает онбординг или главное окно.
- URL окна — путь static export (`widget` → `out/widget.html`).
- Альтернатива — создавать окна из Rust по требованию. Отклонена: capabilities матчатся по метке, а статичный конфиг проще проверить и описать. Цена — четыре webview в памяти; при необходимости плавающие окна можно создавать лениво без изменения спеки.

**2. Закрытие главного окна прячет его, приложение остаётся в трее.**

- `CloseRequested` → `prevent_close` + `hide`.
- `RunEvent::ExitRequested` пропускается только после пункта «Выйти».
- Автозапуск передаёт `--autostart`, и тогда ни одно окно не показывается.

**3. Прозрачность.**

- У виджета и оверлея: `transparent: true`, `decorations: false`, `alwaysOnTop: true`, `skipTaskbar: true`, `shadow: false`, `resizable: false`.
- Для прозрачности на macOS нужен `app.macOSPrivateApi: true` (фича `macos-private-api`). Публикация в Mac App Store не планируется.
- Фон страницы снимается CSS-правилом `:root:has([data-window="floating"]) { background: transparent }`. Корень страниц виджета и оверлея размечен `data-window="floating"`.
- Так не нужен отдельный root layout: static export не даёт сегменту маршрута менять `<html>` и `<body>`.

**4. Скрытие от показа экрана.**

- Поле окна `contentProtected` переключается командой `set_content_protected` (`NSWindow.sharingType = none` / `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`).
- При старте и при изменении `hideOnShare` Rust применяет значение к оверлею.

**5. Кнопки окна по платформам.**

- **macOS.** В `tauri.macos.conf.json` у главного окна и онбординга заданы `titleBarStyle: "Overlay"`, `hiddenTitle: true` и `trafficLightPosition` под нарисованные кнопки. В Tauri на macOS `WindowTrafficLights` рисует прозрачный отступ того же размера, и поверх него — нативные кнопки.
- **Windows.** В `tauri.windows.conf.json` задано `decorations: false`. Заголовок рисует `WindowControls`, кнопки вызывают `minimize`, `toggleMaximize` и `close` текущего окна.
- **Браузер.** Остаётся рисунок macOS, как в макетах.
- **Определение платформы** — по `navigator.userAgent` (`Macintosh` / `Windows`). Это надёжно для WKWebView и WebView2 и не требует плагина.
- **Альтернатива** — `decorations: false` везде и нарисованные «светофоры» на macOS. Отклонена: теряются системные жесты, полноэкранный режим и привычное поведение кнопок.

**6. Трей, автозапуск, горячие клавиши, единственный экземпляр.**

- **Трей — `TrayIconBuilder`** (фича `tray-icon`). Пункт «Настройки» показывает главное окно и шлёт ему типизированное событие `Navigate { route }`, фронтенд делает `router.push`.
- **Автозапуск — `tauri-plugin-autostart`** (LaunchAgent / ключ `Run`).
- **Горячие клавиши — `tauri-plugin-global-shortcut`**, регистрация только из Rust.
  - Фронтенд хранит в настройках сочетания как сейчас (массив клавиш). Rust переводит их в accelerator.
  - Ошибки регистрации возвращаются результатом команды сохранения настроек по каждому сочетанию.
- **Единственный экземпляр — `tauri-plugin-single-instance`.** Он регистрируется первым плагином, колбэк показывает и фокусирует нужное окно.
- **Побочные эффекты настроек** (`launchAtLogin`, `hideOnShare`, `shortcuts`) применяет команда `settings_update` в Rust. Поэтому они работают, из какого бы окна ни пришло изменение.

**7. Права: собственные команды под манифестом.**

- В Tauri 2 команды приложения по умолчанию доступны всем окнам. Чтобы требование «минимальные права» было проверяемым, `build.rs` объявляет `AppManifest::commands([...])`. Тогда каждая команда требует `allow-<command>` в capability.
- **Capability `main`** — окна `main` и `onboarding`: все команды данных, управление окном, autostart.
- **Capability `floating`** — окна `widget` и `overlay`: чтение проектов, людей и звонков, команды старта и ведения звонка, `start-dragging`, `hide`.
- Тест в Rust сверяет список команд из builder tauri-specta со списком манифеста, чтобы новая команда не осталась без прав.

### Хранилище

**8. Стек: `rusqlite` (bundled) + `rusqlite_migration`. Одно соединение за `Mutex`, работа в `spawn_blocking`.**

- Миграции лежат SQL-файлами в `src-tauri/migrations/NNNN_name.sql` и встраиваются в бинарь. Версия хранится в `PRAGMA user_version`.
- Pragma при открытии: `journal_mode=WAL`, `foreign_keys=ON`, `busy_timeout=5000`.
- Файл — `app_data_dir()/grill.db`.
- Команды объявлены `async` и уходят в `spawn_blocking`. Синхронные команды Tauri выполняются на главном потоке и блокировали бы UI (требование «Отзывчивость»).
- Отклонённые альтернативы:
  - `sqlx` — async, но тянет свой рантайм, а compile-time проверки требуют БД при сборке;
  - `tauri-plugin-sql` — SQL из JS, а логика данных нужна в Rust: туда будут писать транскрипт и агент;
  - `diesel` — тяжёлый для двух десятков запросов;
  - пул r2d2 — не нужен при одном пользователе.

**9. Отказ хранилища не роняет приложение.**

- Если открыть базу или применить миграции не удалось, состояние хранилища — `Err`. Это случается, например, когда база новее приложения: `rusqlite_migration` различает этот случай.
- Тогда каждая команда данных отвечает `Storage { message }`, а главное окно показывает экран ошибки с текстом.
- Перед применением миграций к существующей базе Rust копирует файл в `grill.db.bak-v<N>` и хранит две последние копии. Это откат на случай логической ошибки в миграции, которую не ловит транзакция.

**10. Схема (миграция `0001_init`).**

| Таблица | Ключевые поля |
|---|---|
| `projects` | `name`, `description`, `brief` (JSON) |
| `people` | `project_id` → `projects` ON DELETE CASCADE; `name`, `role`, `profile` (JSON) |
| `calls` | `project_id` → CASCADE; `title`, `status`, `started_at`, `ended_at`, `summary` (JSON) |
| `call_participants` | PK (`call_id`, `person_id`), обе ссылки CASCADE |
| `topics` | `call_id` → CASCADE; `title`, `position` |
| `task_cards` | `topic_id` → CASCADE; `call_id`; `fields` (JSON), `decision` |
| `questions` | `call_id` → CASCADE; `topic_id`, `card_id` (nullable, SET NULL); `text`, `status` (`open` / `answered` / `dismissed`), `priority`, `evidence` (JSON) |
| `transcript_segments` | `call_id` → CASCADE; `channel` CHECK (`me` / `others`), `start_ms`, `end_ms`, `text` |
| `settings` | `key` PK, `value` (JSON) |

- Во всех таблицах, кроме `settings` и `call_participants`: `id TEXT PRIMARY KEY` (UUID v7), `created_at` и `updated_at` — `INTEGER`, миллисекунды UTC.
- Индексы — по внешним ключам и `(call_id, start_ms)` у транскрипта.
- Поля, которые ещё меняются в дизайне (бриф, профиль человека, поля карточки, итоги, основания вопроса), хранятся в JSON-колонках. Так не нужна миграция на каждую правку UI. Колонки выделяем, когда по полю понадобится запрос.
- Состав полей при реализации берётся из текущих TS-типов `src/data/*` и `src/features/*/types.ts`, чтобы экраны не потеряли данные.
- «Участник из того же проекта» проверяется в команде, а не триггером: так ошибка приходит в типизированном виде `Invalid`.

**11. Ошибки и события.**

- Ошибка команды: `#[serde(tag = "kind")] enum CommandError { NotFound, Invalid, Storage }`, у каждого варианта есть `message`.
- Событие одно, типизированное: `DataChanged { entity, id, project_id, change: Created | Updated | Deleted }`.
  - Отправляется через `app.emit` во все окна после коммита транзакции.
  - Каскадное удаление шлёт одно событие о корневой записи. Сторы дочерних сущностей перечитывают данные по `project_id`.
- Сегменты транскрипта пишутся пакетом с одним событием на пакет: в задаче 5 частота будет высокой.

### Контракт и фронтенд

**12. Генерация типов: `tauri-specta` `=2.0.0-rc.26` + `specta-typescript`.**

- Builder собирает команды и события.
- `src/bindings.ts` пишется двумя путями:
  - при запуске debug-сборки;
  - тестом `export_bindings` в `cargo test`.
- В CI в джобе `Rust (macos-latest)` после тестов стоит `git diff --exit-code src/bindings.ts`.
- Файл исключён из Biome и из ревью CodeRabbit: он сгенерирован.
- Версия rc закреплена точно. Риск описан ниже.
- Отклонённые альтернативы:
  - `ts-rs` — генерирует только типы, обёртки `invoke` и события пришлось бы писать руками;
  - ручные типы — расходятся молча.

**13. Мост в Effect: `src/effect/tauri.ts`.**

- `call(cmd)` превращает сгенерированный `Promise<Result<T, CommandError>>` в `Effect<T, BackendError>`.
  - `BackendError` — это `Schema.TaggedError` с полем `kind` (`NotFound` / `Invalid` / `Storage` / `Transport`).
  - `Transport` — отказ самого `invoke`.
- `listen(event)` → `Stream`: `unlisten` выполняется в финализаторе, поэтому отписка происходит при прерывании.
- У каждой области к `layerMock` добавляется `layerTauri`.
- `runtime.ts` выбирает набор слоёв один раз при загрузке модуля по `isTauri()` из `@tauri-apps/api/core`. При пререндере это `false`, и используются моки.

**14. Сторы поверх сервисов, mock-режим синхронный.**

- Хуки и сигнатуры `src/data/*` сохраняются, меняется только источник данных:
  - **mock-режим.** Стор стартует с теми же сидами, что сейчас, синхронно. Мутации идут в in-memory репозиторий `layerMock`, который повторяет контракт команд, включая выдачу UUID. Существующие тесты не замечают разницы.
  - **Tauri.** Стор стартует в состоянии `loading` и при первой подписке читает данные через сервис. На `DataChanged` своей сущности он перечитывает список или запись. Мутации ждут ответа команды; ошибка показывается тостом, стор не меняется.
- Перечитывание вместо применения патча выбрано за простоту и согласованность: объёмы данных малы.
- Мастер проекта получает id из ответа `projects_create` и переходит на `routes.project(id)`.

**15. Шесть `api.ts` → `backend.ts` по образцу projects.**

- `api.ts` остаётся React-обвязкой: запускает эффекты через `runCancelable` / `runPromise` и держит стор прогресса.
- Таймеры и имитация уходят в `layerMock`.
- Tauri-слои для них появятся в задачах 3–9. Сейчас в Tauri-режиме используется `layerMock` этих областей: реального бэкенда у звонка, STT и агента ещё нет.

### Долг и качество

**16. Ссылки-кнопки.**

- `linkButtonProps(href)` (`nativeButton: false`, `render: <Link/>`, `role: undefined`) переезжает в `src/lib/link-button.ts`.
- Его используют все места с `nativeButton={false}`: projects, call-widget и onboarding.
- Тест проверяет, что такие элементы — `role="link"`.

**17. DevNavigator.**

- Кнопка переезжает в левый нижний угол: справа внизу во всех окнах живут основные действия.
- В плавающих окнах (`data-window="floating"`) DevNavigator не рендерится.

**18. E2E: Playwright по static export.**

- `bun run build`, затем крошечный Bun-сервер `scripts/serve-out.ts` отдаёт `out/` с разрешением `/path` → `/path.html`.
- Проекты Playwright:
  - `chromium` — ближе к WebView2;
  - `webkit` — ближе к WKWebView.
- Сценарий: онбординг → новый проект → виджет старта → звонок → завершение → итоги и история.
- Отдельная CI-джоба `E2E`. В обязательные проверки ruleset её добавим после пары недель без флаков (открытый вопрос).
- Альтернатива — `tauri-driver` + WebdriverIO. Отложена: не работает на macOS, на основной платформе разработки.

**19. Защита `src/components/ui` от `shadcn add`.**

- Проверено: `shadcn add` без `-o/--overwrite` не перезаписывает существующие файлы, а `--dry-run` и `--diff` показывают изменения заранее.
- Решение:
  - правило в `AGENTS.md`: компоненты в `src/components/ui` — наш код; `shadcn add` запускать только с `--dry-run` / `--diff`, никогда с `-o` и `--all`;
  - конфликтующие изменения переносить руками;
  - восстановление — через git.
- Отклонённые альтернативы:
  - перенос в другую папку — 88 файлов и импорты shadcn;
  - собственный registry — избыточен для одного приложения.

## Risks / Trade-offs

- **[`contentProtected` на macOS 15+ не всегда скрывает окно от захвата через ScreenCaptureKit, которым пользуются Zoom и Chrome.]** → Ручная проверка в Zoom, Meet (Chrome) и Teams на macOS и Windows входит в задачи. Если окно видно, отдельная задача заведёт обход (прятать оверлей при детекте показа экрана). Спека от этого не меняется.
- **[`tauri-specta` — rc.]** → Версия закреплена точно, обновление вручную, сгенерированный файл под diff-проверкой. Если проект забросят, переход на `ts-rs` затронет только `src/effect/tauri.ts`.
- **[`macOSPrivateApi` закрывает Mac App Store.]** → Распространяем через GitHub Releases. Если понадобится App Store, нужно будет обойтись без прозрачных окон.
- **[Static export: путь окна без `.html`.]** → Первая задача фазы окон — проверить в `tauri build`, что `widget` резолвится в `widget.html`. Иначе указываем `widget.html` явно.
- **[Перечитывание по событиям даёт лишние запросы.]** → Объёмы малы. Для транскрипта (задача 5) предусмотрен пакетный режим.
- **[Mock-режим и Tauri-режим расходятся по поведению.]** → `layerMock` реализует тот же контракт, включая ошибки. E2E проверяет моки, а `cargo test` с базой в памяти — команды.
- **[Четыре webview в памяти.]** → Около 30–60 МБ на окно. Если окажется много, плавающие окна станут ленивыми, без изменения спеки.

## Migration Plan

- Сохранённых данных у пользователей нет (только моки), так что `0001_init` — первая версия схемы.
- Откат релиза: старая версия приложения откажется работать с базой новее себя (`Storage`, экран ошибки), а копия `grill.db.bak-v<N>` позволяет вернуть файл.
- Changeset `minor`.

## Open Questions

- Включать ли Biome для `src/components/ui` теперь, когда это наш код. Сейчас папка исключена как «upstream». На эту задачу не влияет.
- Когда сделать джобу `E2E` обязательной проверкой в ruleset `main`.
- Какие действия из настроек — глобальные сочетания, а какие работают только внутри окна. Состав берём из текущего `DEFAULT_SHORTCUTS`; уточнение не меняет механизм.
