## Context

Аудит экрана «Настройки» (2026-11-12) показал:
- **Нет Tauri-слоя.** `SettingsBackend` есть только как `layerMock`, и `src/effect/runtime.ts:60` подставляет его в `TauriLayer`. Поэтому `inputLevel`, `soundCheck`, `checkAgent`, `signInAgent`, `moveRecordings`, `exportData`, `deleteAllData`, `revealInFinder` и `openExternal` в приложении — таймеры и случайные числа.
- **Любой ключ сохраняется.** Настройки пишутся через `settingsUpdate`, а Rust сохраняет любой ключ (`storage/settings.rs:149`, `_ => true`).
- **Захват.** Микрофон всегда берётся по умолчанию (`audio/sources.rs:184`, `default_input_device()`). Системный звук — глобальный tap без своих процессов (`audio/mac/tap.rs:133`).
- **Готовые команды, которые экран не использует:**
  - `audioLevelStart` / `audioLevelStop` и события `audio-level` / `audio-level-stopped`;
  - `speechMicCheck` (`commands.rs:1532`, `mic_check::listen_to_microphone`);
  - `agentStatus` → `AgentState { notInstalled | needsLogin{version} | ready{version, subscriptionType} | error }`;
  - `agentLoginStart` / `Submit` / `Cancel`;
  - `callAudioDelete` (`storage/recordings.rs:344`, `audio_deleted_at`).
- **Записи** лежат в `<data_dir>/recordings` (`recording/store.rs:82-97`).
- **Доля лимита** пишется в `agent_calls.utilization` каждого вызова.
- **Плагин** `tauri-plugin-opener` подключён.

Ключи, которые никто не читает: `microphone`, `systemAudio`, `interfaceLanguage`, `theme` (тема принудительно светлая), `recordingsFolder`, `agentSignedIn`, `finalCheck`, `audioRetention`, `transcriptRetention`.

## Goals / Non-Goals

**Goals:** каждая настройка в приложении настоящая. Звук слушает то устройство, которое выбрано. Сроки хранения исполняются. Фальшивые контролы убраны.

**Non-Goals:**
- захват звука только из одного приложения;
- перенос папки записей;
- экспорт данных;
- перевод интерфейса;
- тёмная тема;
- выход из CLI;
- финальная проверка по таймеру.

## Decisions

### 1. Микрофон: имя устройства и общий выбор

- **Список.** `audio::inputs::list() -> Vec<InputDevice { id, name, isDefault }>` строится по `cpal::default_host().input_devices()`. `id` — имя устройства: cpal 0.15 не даёт стабильных идентификаторов, а имя CoreAudio и WASAPI для одного устройства постоянно.
- **Изменения списка.** Наблюдатель опрашивает список раз в секунду, пока на него подписано окно, и шлёт событие `audio-inputs-changed` с новым списком. Опрос выбран потому, что слушатели CoreAudio и WASAPI — два разных кода. Скрытое окно теряет подписку и получает `audio-inputs-stopped`, как с индикаторами уровня; получив фокус, оно подписывается снова и перечитывает список.
- **Хранение.** Ключ `microphone`: `"system"` («Как в системе», по умолчанию) или имя устройства. Старое значение `"airpods"` и любое неизвестное имя при чтении трактуются как имя, которого нет, и дают плашку. Демо-значения `"airpods"` и `"macbook"` миграции настроек заменяют на `"system"`.
- **Открытие.** `audio::sources::open_microphone(choice)` ищет устройство по имени, иначе берёт устройство по умолчанию и возвращает `Opened { device, fallback: bool }`. Им пользуются три места:
  - запись (`recording/manager.rs`), при старте и при переподключении канала: раз в секунду проверяется, не появился ли выбранный микрофон, и если появился — переключение, как при сбое;
  - проверка уровня (`audio_level_start("microphone")`): при смене настройки захват перезапускается;
  - `speech_mic_check`.
- **Пропажа.** Время, когда выбранный микрофон пропал, держит в памяти `MicChoice`. Его отдают команда `audio_inputs_get -> { devices, selected, missingSince? }` и событие.

### 2. Системный звук

Выбор источника убирается, ключ `systemAudio` удаляется из белого списка (решение 6). Раздел показывает строку «Звук других приложений, без звука Grill» и состояние доступа из существующей проверки разрешений (`permissions`). Индикатор системного звука — `audioLevelStart("system")`.

### 3. Проверка звука

`speech_mic_check` получает выбор микрофона из решения 1. Экран вызывает команду и показывает результат или причину: нет модели, нет доступа. Длительность и VAD остаются, как в онбординге.

### 4. Папка, место, Finder

- **Команда** `recordings_info -> { path, bytes, calls }`. `bytes` — размер файлов в `<data_dir>/recordings`, считается в `spawn_blocking`. `calls` — число звонков, у которых есть аудио и `audio_deleted_at IS NULL`. Папку команда создаёт, если её ещё нет, чтобы «Показать в Finder» работал на новой установке.
- **Finder.** «Показать в Finder» вызывает `revealItemInDir(path)` плагина opener. Прав на открытие произвольных путей не нужно, путь отдаёт Rust.
- **Удаление ключа.** `recordingsFolder` удаляется.

### 5. Сроки хранения

- **Где.** Модуль `storage::retention` с функцией `purge_at(now)`.
- **Аудио.** Звонки, у которых `ended_at < now - audioRetention` и аудио ещё не удалено, проходят тот же путь, что `call_audio_delete`: файлы удаляются, ставится `audio_deleted_at`.
- **Расшифровки.** У звонков старше `transcriptRetention` удаляются строки `transcript_segments`, а в `recordings` ставится `transcript_deleted_at`. Это колонка миграции `0011`.
- **Что остаётся.** Итоги, карточки и вопросы с основаниями остаются. Ссылки на сегменты в основаниях ведут в пустоту, поэтому страница звонка и переходы к фразам показывают «расшифровка удалена по сроку хранения» вместо перехода.
- **Идущая запись** не трогается.
- **Запуск.** Задача запускается через 30 с после старта приложения и затем раз в 24 часа. Если что-то удалено, шлётся по одному `DataChanged` на каждый затронутый звонок: страница звонка перечитывает только свой.
- **Значения ключей.** `audioRetention` — `"7" | "30" | "90" | "never"`, по умолчанию `"never"`. `transcriptRetention` — `"90" | "180" | "365"` дней. Это сохранённые значения экрана: «3 месяца», «6 месяцев», «1 год».

Альтернатива — удалять при открытии звонка. Отвергнута: менеджер ждёт, что срок исполняется сам.

### 6. Белый список ключей и удаление лишних

- **Белый список.** В `storage::settings` появляется перечень известных ключей с проверкой значения. Неизвестный ключ даёт `Invalid`.
- **Удаляемые ключи:** `systemAudio`, `recordingsFolder`, `interfaceLanguage`, `finalCheck`, `agentSignedIn`.
- **Тема.** `theme` остаётся: «Светлая» выбрана, остальные недоступны. Это честная пометка «скоро» по дизайну.
- **Миграция.** `0011` удаляет строки этих ключей и заменяет `microphone = 'airpods'` на `'system'`; `0012` так же заменяет `'macbook'`.
- **Фронтенд.** Убираются контролы, поля стора и адаптеры этих ключей.

### 7. Агент

- **Состояние.** Раздел читает `agentStatus` при открытии и по «Проверить». Показываются путь из `agentPath` (`null` — «найден автоматически» и путь, который нашёл Rust), версия, состояние входа и тип подписки.
- **Вход.** «Войти» использует общий поток входа из онбординга (`agentLoginStart`, `Submit`, `Cancel`) в диалоге.
- **«Указать другой»** вызывает `agentStatus` с новым путём: команда `agent_check_path(path) -> AgentState` без сохранения. Сохранение идёт только при состоянии не `notInstalled` и не `error`.
- **Лимит.** Команда `agent_usage -> { utilization, measuredAt } | null` берёт последнюю строку `agent_calls`, где `utilization` не `NULL`.
- **Что убирается.** «Выйти» и ключ `agentSignedIn`.
- **Интеграции.** Версия агента в «Интеграциях» берётся из того же `agentStatus`.

### 8. «Удалить всё»

- **Сводка.** Команда `data_summary -> { projects, calls, bytes }`.
- **Удаление.** `data_delete_all`:
  - удаляет строки всех таблиц данных одной транзакцией;
  - удаляет файлы в папке записей;
  - удаляет секреты коннекторов из `SecretStore`;
  - сбрасывает все настройки, включая `agentPath`, чтобы онбординг прошёл заново;
  - отмечает онбординг непройденным;
  - не даёт начаться звонку, пока идёт удаление (в том числе «Сразу записывать»);
  - загружает окно онбординга заново с первого шага: после онбординга оно было только скрыто.
- **Фронтенд** вызывает команду и открывает онбординг. Удаление по сторам из `privacy-section.tsx` заменяется этой командой.

### 9. `SettingsBackend.layerTauri`

Методы `inputLevel`, `soundCheck`, `checkAgent`, `signInAgent`, `revealInFinder` и `deleteAllData` получают реализации на командах выше. `moveRecordings`, `exportData` и `openExternal` удаляются из сервиса вместе с контролами. `openExternal` для GitHub «скоро» не нужен. `layerMock` остаётся для демо и `/dev` с теми же сигнатурами.

## Risks / Trade-offs

- **[Имя устройства не уникально]** → Два одинаковых USB-микрофона дают одно имя. Берётся первый — редкий случай.
- **[Опрос списка раз в секунду]** → Идёт только пока подписано окно (раздел «Звук» или запись). Стоит дёшево.
- **[Удаление расшифровок ломает переходы к фразам]** → Явная пометка «расшифровка удалена по сроку хранения» на странице звонка, итоги остаются.
- **[Удалить всё необратимо]** → Подтверждение с настоящими числами, как раньше.

## Migration Plan

Миграция `0011` добавляет `recordings.transcript_deleted_at`, удаляет неиспользуемые ключи настроек и заменяет `microphone = 'airpods'` на `'system'`; `0012` заменяет `'macbook'` на `'system'`. Откат кода без отката базы безопасен: удалённые ключи никто не читал.
